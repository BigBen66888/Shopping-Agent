# 评测驱动的修改记录

所有有写入动作的购物评测都使用 `eval_v3/results/` 下的隔离 SQLite；没有操作正式购物库。

| 位置 | 修改 | 触发证据与验证 |
|---|---|---|
| `shopping_agent/agents/main_agent.py` | 对独立双搜索或“读状态＋搜索”明确要求同轮双 `delegate_search`；已加购和答案引用的商品卡优先展示；多路搜索的候选按路交错放入八张卡。 | 旧自然复杂集委派率为 0；修改后 9/9 首步探针双委派，自然复杂任务两次运行分别 6/6 和 5/6 委派，3/3 写入任务商品卡对齐。双商品上下文案例又发现首路搜索独占八张卡，已加交错展示并写单元测试。 |
| `shopping_agent/agents/search_agent.py` | 将 `mechanical keyboard` 等自然类目短语归到类目名词；品牌字段缺失时可用标题验证品牌；显式颜色按标题、描述和属性硬过滤。 | 同一机械键盘检索传 `category="mechanical keyboard"` 原来返回 0，传 `keyboard` 返回 8；双商品聚焦复测在修复后出现真实鼠标与机械键盘卡。白色背包聚焦复测验证颜色过滤。 |
| `shopping_agent/deepseek.py` | 对无正文/输出长度耗尽的响应有限重试并逐步增大输出上限；把非法工具 JSON 和可修正的参数错误回传给模型。 | 七轮会话中的摘要请求曾以 `finish_reason=length`、正文 0 字结束；另有非法 JSON 和不在候选池的商品 ID 使整轮中断。定点重试与单元测试通过。 |
| `shopping_agent/memory/context_manager.py` | 摘要 API 输出上限提高；新摘要加入后若仍超预算，继续把较早消息并入摘要，同时保留最近两条原文。 | 双商品案例第 6 轮原来报“上下文仍超出预算”；从原隔离会话续跑该轮后完成。 |
| `shopping_agent/service.py` | 长期记忆按时间新到旧读取；同主题同槽位的新记忆把旧记录标为 `SUPERSEDED`；记忆抽取失败不再丢弃已完成购物轮次。 | 6/6 跨会话颜色、品牌、预算、尺码冲突测试通过；多轮探针曾因一次记忆抽取返回非法内容而失去整个回答。 |
| `shopping_agent/memory/conflicts.py` | 新增保守的主题和偏好槽位识别。 | 未能明确识别主题/槽位时保留原记录，避免误删不相关偏好。 |
| `eval_v3/` | 本地生成官方 250 条三档检索输入；新增四路检索、B 完整任务、C 真实逐轮会话、D 冲突评测、可行性检查和汇总脚本。 | 原始官方自然语言 query 没有用于纯检索评测；A 全程 0 模型 API 调用。 |
| `eval_v2/` | 删除旧 Python 评测执行脚本；仅保留历史数据、结果和归档说明。当前所需原始数据与指标函数均迁入 `eval_v3/`。 | `eval_v3` 独立脚本导入通过，数据生成前后 SHA256 相同；删除后全量测试 32/32 通过。 |
| `tests/` | 更新 `_runtime` 的内部返回值测试；增加八卡平衡、空响应重试、工具参数错误恢复和记忆冲突测试。 | 最新全量测试结果见最终报告。 |

测试口径修正：B 的旧评测器只看主 Agent 工具调用，漏掉子 Agent 的 `read_state`；后续又发现只认子 Agent `read_state` 会把主 Agent 直接完成的读状态＋搜索误判失败。旧 SQLite 复用还把上次购物车内容误算为本轮写入。`eval_v3/multiagent_full.py` 同时统计主/子真实调用，并为每次运行创建空的隔离库。原始误判结果保留在 `eval_v3/results/baseline/`。
