## 结论与限制

官方 `synthesize_product_test.jsonl` 未在工作区找到；尝试规划稿推定的 GitHub 原始路径返回 404，仓库 API 返回 403 限流。本次 A 使用自建 20 条，不能称为官方 250 条结果。该脚本提供 `--official` 参数；若提供官方文件，会先核对全部 ID，未匹配则拒绝评分。

本机 CPU 精排 P95 达 22.1 秒，是最明显的响应速度瓶颈。A 集只有 20 条，B2 相对 B1 的 Recall@8 低 5 个百分点，不能据此断言融合普遍退步；B3 达 40%，其 bootstrap 95% 区间为 20%–60%。

26 条 Agent 用例都达成了这里定义的可观察目标，但均由主 Agent 直接调用工具，委派率为 0。因而本次只能证明任务链路可用，尚不能证明子 Agent 协同或并行加速。复杂任务 P95 达 55.7 秒。BX03 首次带有不匹配的 category 参数导致 0 结果，随后重试成功，提示结构化类目过滤较脆弱。

上下文初版题目只问“最早的要求”，3 条型号题的回答失败；改为明确询问型号、预算或规格后，20/20 条答对。初版逐条结果保存在 `context_initial.json`，说明题目措辞会显著影响这一指标。

验证：`python -m pytest -q` 为 19 passed。旧评测脚本、旧 harness 和旧 `eval/` 已清理；前端与核心业务源码没有改动。

本次跳过了需要主观标注或额外基线的并行加速比、最终回答 Grounded Rate、语义冲突解析率，以及 50 轮会话增长曲线。后续最值得补的是最终推荐正确性人工标注，以及有明确委派收益的任务。
