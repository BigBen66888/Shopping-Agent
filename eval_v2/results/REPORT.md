## 1. 官方 250 条检索集：低召回的原因

从 [ShoppingBench `data/` 目录](https://github.com/yjwjy/ShoppingBench/tree/main/data) 取得官方 product 文件；250 条、250/250 个商品 ID 与本地语料匹配。NL query 与标题原文分开评测。

| 检索口径 | Recall@8 | Recall@20 | 说明 |
|---|---:|---:|---|
| BM25，自然语言 | 34.0% | 42.4% | 全字段 BM25 |
| 向量，自然语言 | 13.2% | 20.0% | FAISS nprobe=64 |
| 等权 RRF，自然语言 | 28.8% | 38.0% | 旧线上配置 |
| BM25，商品标题 | 90.8% | 95.6% | 核对索引与目标是否可检出 |
| 向量，商品标题 | 91.6% | 94.4% | 核对向量索引 |

BM25:向量 RRF 权重改为 **1.5:1** 后，250 条 Recall@8 从 28.8% 到 32.8%；MRR@8 从 0.165 到 0.185，配对 bootstrap 95% 差值区间 **+1.2 至 +7.2 个百分点**。

当前线上 BM25 前 40 与向量前 80 的候选并集只覆盖 56.0% 的指定 ID；精排不可能找回候选之外的目标。标题原文的高召回和 250/250 的 ID 匹配排除了语料错位。FAISS nprobe 提高到 256 时，自然语言 Recall@8 仍为 13.2%，也不是 IVF 搜索探针不足。

官方自然语言常包含商品标题未体现的服务、价格或属性，且有个别条件与目标商品本身矛盾，例如 O025 要求 Ford 散热器水壶，标注商品标题却是 Honda CR-V。单一指定 ID 的 Recall 衡量定位该商品的能力，不能直接等同于推荐商品的相关性。

在均匀覆盖官方文件的 **20 条子样本** 上，完整线上三档结果如下（与上表 250 条不可直接当作同一样本比较）：

| 配置 | Recall@8 | MRR@8 | NDCG@8 | Precision@8 | P95 延迟 |
|---|---:|---:|---:|---:|---:|
| 仅向量 | 20.0% | 0.135 | 0.151 | 2.5% | 507 ms |
| 加权 RRF | 35.0% | 0.217 | 0.250 | 4.4% | 8879 ms |
| RRF + BGE 精排 | 30.0% | 0.225 | 0.245 | 3.8% | 34642 ms |

单一标注 ID 下 Precision@8 的理论上限为 12.5%。20 条里精排的 Recall@8 比融合低 5 个百分点，NDCG@8 也略低，而 P95 增至 34.6 秒；小样本不足以证明精排改善质量，当前应优先改善候选召回并另建多相关商品标注。
